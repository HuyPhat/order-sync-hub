# Orders: Migration, Models, Associations and createOrder Implementation Plan

> **For agentic workers:** Implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `orders` and `order_items` tables, typed Sequelize models with associations, and a `createOrder(items)` service that snapshots prices and writes the order and its items in one transaction, with tests proving that a failure saves nothing.

**Architecture:** One migration creates both tables. Models follow the `Product` pattern and are associated in a single `src/models/index.ts`. `createOrder` validates input, then runs one managed Sequelize transaction: load and share-lock the products, snapshot prices, total with decimal.js, create the order and items. Rollback behavior is proven by integration tests that run against a separate `order_sync_hub_test` database, kept out of `pnpm test` by their own vitest config and script.

**Tech Stack:** Node 24, TypeScript 7, Sequelize 6, mysql2, umzug, MySQL 8.4 (Docker Compose), Vitest 5, decimal.js 10.

**Spec:** `docs/superpowers/specs/2026-10-11-orders-design.md` (read it first; this plan implements it). One refinement made while planning: the spec said foreign-key attributes use Sequelize's `ForeignKey<>` helper type; a compile probe showed that helper makes `orderId` and `productId` **optional** when creating an item, so this plan declares them as plain `number` (required). Task 2 pins this.

## Global Constraints

- Work on a new branch `feature/orders`, never on `main`.
- Start state: `pnpm test` passes with **50 tests**, `pnpm typecheck` and `pnpm format:check` are clean, and MySQL is running and healthy (`docker compose ps`).
- `src/config.ts` is the only file that reads `process.env`.
- `pnpm test` never touches a database. Only `*.integration.test.ts` files do, and only against a database whose name ends in `_test`.
- Relative imports end in `.js`; type-only imports use the inline `type` modifier; code is formatted by Prettier (`pnpm format` before committing; `pnpm format:check` must pass).
- Money is a `string` in TypeScript and a `DECIMAL` in MySQL. Use `import { Decimal } from 'decimal.js'` (the **named** import: the default import runs but fails `tsc` under `module: nodenext`).
- Code that needs associations imports models from `src/models/index.js`, never from the individual model files.
- Tables are created only by migrations; models never call `sync()`.
- Migration filenames come from `pnpm db:create` (the tool makes the timestamp prefix).
- Commit messages carry no `Co-Authored-By` line (user preference). Nothing is pushed by this plan.

## Review Focus

1. **A failure after the order row is inserted must leave no order behind.** Pinned in Task 5 by two tests: `OrderItem.bulkCreate` rejecting after `Order.create` ran, and MySQL itself rejecting an out-of-range quantity.
2. **"Unknown product" proves nothing about rollback** (it fails before any write), so it must not be the only failure test. Task 5 keeps it as a behavior check and adds the two real proofs.
3. **A later price change must not alter a saved order.** Pinned in Task 4 ("keeps the price it saw").
4. **Repeated products merge into one line with the right total.** Pinned in Task 4.
5. **Bad input (empty order, quantity 0, negative, fractional, NaN, invalid product id) must fail before a transaction is opened.** Pinned in Task 4's offline tests.
6. **A missing foreign key must be a compile error** (the `ForeignKey<>` trap). Pinned in Task 2 with `@ts-expect-error`.
7. **The integration setup must refuse to run on a database not named `*_test`** (it drops every table). Pinned in Task 3 step 9.
8. **Models and migrations must not drift.** Pinned in Task 3 by `schema.integration.test.ts`.

```ts
describe('Order model', () => {
  it('maps to the orders table', () => {
    expect(Order.tableName).toBe('orders');
  });

  it('declares exactly the migration columns', () => {
    expect(Object.keys(Order.getAttributes()).sort()).toEqual([

      'status',
      'total',
      'updatedAt',
    ]);

    const attrs = Order.getAttributes();
    expect(attrs.status?.allowNull).toBe(false);
    expect(attrs.status?.defaultValue).toBe('pending');
    expect(attrs.total?.allowNull).toBe(false);
  });

  it('limits status to pending, paid and cancelled', () => {
    // Sequelize does not type the ENUM's values, hence the cast.
    const type = Order.getAttributes().status?.type as unknown as { values: string[] };
    expect(type.values).toEqual(['pending', 'paid', 'cancelled']);

  it('uses DECIMAL(12,2) for total', () => {
    expect(String(Order.getAttributes().total?.type)).toBe('DECIMAL(12,2)');

  it('builds with a pending status by default, without touching the database', () => {
    const order = Order.build({ total: '10.00' });
    expect(order.total).toBe('10.00');
    expect(order.status).toBe('pending');

  it('rejects wrong shapes at compile time', () => {
    // Checked by `pnpm typecheck`: each @ts-expect-error fails the typecheck
    // if the line below it stops being an error.
    // @ts-expect-error total is required
    Order.build({});

    Order.build({ total: 10 });
```

```ts
import {
  DataTypes,
  Model,
  type CreationOptional,
  type InferAttributes,
  type InferCreationAttributes,
  type NonAttribute,
} from 'sequelize';
import { sequelize } from '../db/sequelize.js';
import type { OrderItem } from './order-item.js';

export type OrderStatus = 'pending' | 'paid' | 'cancelled';

export class Order extends Model<
  InferAttributes<Order, { omit: 'items' }>,
  InferCreationAttributes<Order, { omit: 'items' }>
> {
  declare id: CreationOptional<number>;
  declare status: CreationOptional<OrderStatus>;
  // DECIMAL is a string on purpose, as for Product.price.
  declare total: string;
  declare createdAt: CreationOptional<Date>;
  declare updatedAt: CreationOptional<Date>;

  // Filled only when queried with include: 'items'.
  declare items?: NonAttribute<OrderItem[]>;
}

Order.init(
  {
    id: { type: DataTypes.INTEGER.UNSIGNED, primaryKey: true, autoIncrement: true },
    status: {
      type: DataTypes.ENUM('pending', 'paid', 'cancelled'),
      allowNull: false,
      defaultValue: 'pending',
    },
    total: { type: DataTypes.DECIMAL(12, 2), allowNull: false },
    createdAt: DataTypes.DATE,
    updatedAt: DataTypes.DATE,
  },
  { sequelize, tableName: 'orders' },
);
```

```ts
import {
  DataTypes,
  Model,
  type CreationOptional,
  type InferAttributes,
  type InferCreationAttributes,
  type NonAttribute,
} from 'sequelize';
import { sequelize } from '../db/sequelize.js';
import type { Order } from './order.js';
import type { Product } from './product.js';

export class OrderItem extends Model<
  InferAttributes<OrderItem, { omit: 'order' | 'product' }>,
  InferCreationAttributes<OrderItem, { omit: 'order' | 'product' }>
> {
  declare id: CreationOptional<number>;
  // Plain numbers on purpose: Sequelize's ForeignKey<> helper would make these optional when
  // creating an item, so a missing orderId or productId would compile and only fail in MySQL.
  declare orderId: number;
  declare productId: number;
  declare quantity: number;
  // A snapshot of Product.price at the time of the order, not a live reference.
  declare unitPrice: string;
  declare createdAt: CreationOptional<Date>;
  declare updatedAt: CreationOptional<Date>;

  declare order?: NonAttribute<Order>;
  declare product?: NonAttribute<Product>;
}

OrderItem.init(
  {
    id: { type: DataTypes.INTEGER.UNSIGNED, primaryKey: true, autoIncrement: true },
    orderId: { type: DataTypes.INTEGER.UNSIGNED, allowNull: false },
    productId: { type: DataTypes.INTEGER.UNSIGNED, allowNull: false },
    quantity: { type: DataTypes.INTEGER.UNSIGNED, allowNull: false },
    unitPrice: { type: DataTypes.DECIMAL(10, 2), allowNull: false },
    createdAt: DataTypes.DATE,
    updatedAt: DataTypes.DATE,
  },
  { sequelize, tableName: 'order_items' },
);
```

**Create `test/integration-setup.ts`:**
```ts
import { TEST_DATABASE } from './test-database.js';

// Runs once before the integration tests: rebuild the test database schema from the migrations.
export default async function setup() {
  process.env.MYSQL_DATABASE = TEST_DATABASE;

  const { config } = await import('../src/config.js');
  // Reverting every migration drops all tables. Never do that to a real database.
  if (!config.db.name.endsWith('_test')) {
    throw new Error(
      `Refusing to reset "${config.db.name}": integration tests only run against a database whose name ends in "_test".`,
    );
  }

  const { migrator } = await import('../src/db/migrator.js');
  const { sequelize } = await import('../src/db/sequelize.js');

  await migrator.down({ to: 0 }); // clean slate: revert everything...
  await migrator.up(); // ...and apply every migration again

  return async () => {
    await sequelize.close();
  };
}
```

```ts
import { Decimal } from 'decimal.js';
import { sequelize } from '../db/sequelize.js';
import { Order, OrderItem, Product } from '../models/index.js';

export interface OrderLine {
  productId: number;
  quantity: number;
}

export class InvalidOrderError extends Error {
  override name = 'InvalidOrderError';
}

export class ProductNotFoundError extends Error {
  override name = 'ProductNotFoundError';
  constructor(readonly productIds: number[]) {
    super(`Unknown product id(s): ${productIds.join(', ')}`);
  }
}

const isPositiveInteger = (n: unknown): n is number => Number.isInteger(n) && (n as number) >= 1;

// Checks the input and merges repeated products into one line (quantities add up).
function normalizeLines(lines: OrderLine[]): OrderLine[] {
  if (lines.length === 0) throw new InvalidOrderError('An order needs at least one item');

  const merged = new Map<number, number>();
  for (const { productId, quantity } of lines) {
    if (!isPositiveInteger(productId)) throw new InvalidOrderError(`Invalid productId: ${productId}`);
    if (!isPositiveInteger(quantity)) throw new InvalidOrderError(`Invalid quantity: ${quantity}`);
    merged.set(productId, (merged.get(productId) ?? 0) + quantity);
  }
  return [...merged].map(([productId, quantity]) => ({ productId, quantity }));
}

// Loads the products, snapshots their current prices into the items, and writes the order and
// all its items in ONE transaction: if anything throws, nothing is saved.
export async function createOrder(lines: OrderLine[]): Promise<Order> {
  const wanted = normalizeLines(lines);

  return sequelize.transaction(async (transaction) => {
    // LOCK IN SHARE MODE: nobody can change these prices until this transaction ends.
    const products = await Product.findAll({
      where: { id: wanted.map((line) => line.productId) },
      transaction,
      lock: transaction.LOCK.SHARE,
    });
    const priceById = new Map(products.map((product) => [product.id, product.price]));

    const unknown = wanted.filter((line) => !priceById.has(line.productId));
    if (unknown.length > 0) throw new ProductNotFoundError(unknown.map((line) => line.productId));

    const items = wanted.map((line) => ({
      productId: line.productId,
      quantity: line.quantity,
      unitPrice: priceById.get(line.productId) as string,
    }));
    const total = items
      .reduce((sum, item) => sum.plus(new Decimal(item.unitPrice).times(item.quantity)), new Decimal(0))
      .toFixed(2);

    const order = await Order.create({ status: 'pending', total }, { transaction });
    await OrderItem.bulkCreate(
      items.map((item) => ({ ...item, orderId: order.id })),
      { transaction },
    );

    return order.reload({ include: 'items', transaction });
  });
}
```

### Reference for later research: "Integer cents in JS"

A dependency-free alternative to decimal.js. Convert each price to integer cents, add, convert back:
```ts
// '19.99' -> 1999n ; assumes exactly two decimals, which DECIMAL(10,2) guarantees
const toCents = (price: string): bigint => BigInt(price.replace('.', ''));
const fromCents = (cents: bigint): string => {
  const s = cents.toString().padStart(3, '0');
  return `${s.slice(0, -2)}.${s.slice(-2)}`;
};
const total = items.reduce((sum, i) => sum + toCents(i.unitPrice) * BigInt(i.quantity), 0n);
fromCents(total); // '40.28'
```

| | decimal.js (chosen) | Integer cents |
|---|---|---|
| Dependency | one package | none |
| Unit testing the total | possible, but the service owns the sum | easy: a pure function |
| Flexibility | any precision, tax rates, division | fixed at two decimals; negatives and larger scales need care |
| Risk | import quirk under `nodenext` (named import) | hand-rolled parsing must be tested well |

With two-decimal prices, a float sum followed by `toFixed(2)` usually produces the same string, so the tests cannot tell decimal.js from floats. The benefit of either approach is correctness by construction, not something these tests demonstrate.
